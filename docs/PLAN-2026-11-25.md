## 0.15 → 0.18 与桌面壳相关的变化

- **0.16 起导出 HTML 换实现**：不再用字符串替换 patch SDK 模板（B2 那套），改为 `getPackageDir()` 找到内置 pi CLI 包，调 `dist/core/export-html` 导出。→ `patch-pi-web-export.mjs` 在 0.18 上必然 skipped，已成死代码。
- 0.16：扩展加载错误/警告改为通知；`setEditorText`/`pasteToEditor` 修正；Stop 行为对齐 TUI。
- 0.17：Agents 条、侧聊可搜索、单文件上传上限 25MB → 100MB。
- 0.18：Next 16.4.6、子 Agent steer 进运行中回合、PlantUML、文件夹丢失可 fork；修 `PI_WEB_PASSWORD` 等环境变量泄漏给子进程。
- **pi 1.6.0 breaking**：扩展组件 `render()` 返回 `readonly string[]`，原地修改 `super.render()` 的插件要改成先复制。
- pi 1.6.0 行为变化：`find` 工具路径模式改为相对搜索目录（`src/*.ts` 不再匹配 `pkg/src/a.ts`）。

## 事后补记（实施记录，0.3.4-beta.1）

> 按存档规矩，正文不动；实施与批准方案的差异记在这里。

**差异一：内置 Node 不是 22.23.5，而是 24.22.3（子龙 2026-11-25 晚拍板）**

原方案（批准口径第 2 条）是 22.23.4 → 22.23.5「只升 patch」。实施后首次真机验收即发现：App 内 `bash` 工具被 context-mode 的 PreToolUse hook 拒绝、`ctx_execute` 同错，报
`Context Mode needs Node 24.15.0 or newer; you have v22.23.5`。侧车里的 pi 进程跑的是包内 `runtime/node`，所以内置 Node 版本 = 扩展/hook 的运行时，22.x 直接判死。

- 选项：24.22.3（Krypton，2026-11-10 安全版，与本机 nvm 一致）/ 26.13.1（Lithium，Active LTS）/ 保持 22 + 关掉 context-mode。
- 决定：**24.22.3**。理由是满足 `>=24.15.0`、与终端版本一致，且 pi-web 0.18 / node-pty（N-API）/ Next 16 在 24 上风险最低。
- 往返：`sidecar.json` 改一行 → `rm -rf sidecar` → `npm run sidecar` → `smoke` → `cargo test` → 重建 → `smoke-app`，全部通过。

**差异二：新增一处测试修复 `scripts/smoke-app.mjs`（批准方案未含）**

`smoke-app` 首轮在 Node 24 构建上报「侧车没有在监听端口」，实为误报：`attach_policy` 默认 `same-version`，本机 30141 有同版本 pi-web 在跑，测试实例**附着**过去、自己不起服务（日志 `[attached] 已连接本机运行的 pi-web v0.18.0`）。修复：两个临时配置都写 `attach_policy: "never"`。产品行为（同版本附着，避免两份服务写同一份会话）**未改动**。

**差异三：验收改为独立测试实例（子龙选择）**

不覆盖 `/Applications/Pi Web Desktop.app`（0.3.3 在用），而是复制成 `/Applications/Pi Web Desktop 0.3.4-beta.1.app`，配 `PIWEB_CONFIG_DIR=~/Library/Application Support/com.zilong.piweb.desktop-034beta`、`port: 30341`、`attach_policy: never` 独立跑；会话仍共享 `~/.pi/agent`。验收通过后再覆盖正式安装。

**验收状态**：自动化全绿（manifest `0.18.0 / 1.6.0 / v24.22.3`、`smoke` 导出 279.0 KB、`cargo test` 28 项、`smoke-app` 六项）；**子龙 2026-11-25 晚在 30341 隔离实例真机验收通过**（context-mode 的 `bash`/`ctx_execute` 恢复、导出、折叠、侧聊/Agents 条、终端、问卷插件均正常）。据此 tag `v0.3.4-beta.1`。
