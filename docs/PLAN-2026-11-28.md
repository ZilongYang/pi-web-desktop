## 0.19.0 与桌面壳相关的变化

- **安全（#1827）**：页面默认发送 `Content-Security-Policy: frame-ancestors 'self'` 与 `X-Frame-Options: SAMEORIGIN`；其他站点不能再把 pi-web 嵌进 iframe。若在别的 origin 门户里嵌入，需要 `PI_WEB_FRAME_ANCESTORS` 列出这些源。
  - 对本壳**无影响**：外壳用 `WebviewUrl::External` **顶层加载** pi-web（不是 iframe）。已在 /tmp 实测响应头确为上述两值，首页与接口均 200。
- 新增设置：引导消息 / 后续消息模式（`steeringMode` / `followUpMode`）、**网络代理 httpProxy**、notices 四项开关。
- 新功能：`#` 引用其他会话、侧栏按时间排序、行号链接跳到对应行、折叠工具步骤显示总费用。
- 修复：超大会话条目延迟加载不再阻塞、会话搜索缓存、侧聊可搜索、CSP/离线判断统一等。
- **pi 1.6.1 breaking**：去掉 `showCacheMissNotices`，拆成 `notices.cacheMisses` / `cacheWarming` / `compactionCosts` / `reasoningDrops`。pi-web 0.19 已适配；**本壳没有读写该设置的代码**，无影响。

## 事后补记（实施记录）

> 按存档规矩，正文不动；实施与批准方案的差异记在这里。

**差异一：侧车体积与折叠补丁引用数（与预验证数字不同，属裁剪所致）**

方案里只写了「重装后核对 manifest」。实际：裁剪前 606MB / 27776 文件 → **裁剪后 425MB / 19878 文件**；折叠补丁在**未裁剪的 /tmp 副本**里是 12 个引用，**裁剪后**是 8 个引用（部分引用在已删除的 `.map` 里）——与 0.3.4-beta.1 的「8 个引用」一致。锚点、改名、旧 chunk 清理都正常。

**差异二：`smoke:app` 需要非沙箱环境（补充说明，不是代码改动）**

DSH 的 workspace-write 沙箱不允许写 `~/Applications`，`ditto` 直接 `Operation not permitted`。改用一次 danger-full-access 跑通，六项断言全绿。这是执行环境限制，与产物无关；CI 与普通终端不受影响。

**差异三：验收实例的配置目录与通道**

端口仍按方案用 30341，但配置目录新建 `com.zilong.piweb.desktop-034beta2`（不和 beta.1 的 `-034beta` 混用，避免两个实例抢同一份 `config.json`），`update_channel` 设为 `beta`（方便后面测 beta 通道升级）。会话仍共享 `~/.pi/agent`。

**执行记录**：`npm run sidecar` → manifest `0.19.0 / 1.6.1 / v24.22.3`；`npm run smoke` 全绿（导出 279.0 KB）；`cargo test` 28 项；`tauri build` 1m37s / 447.57 MiB；`smoke:app` 六项全绿；隔离实例 `/Applications/Pi Web Desktop 0.3.4-beta.2.app` 启动自检 HTTP 200、CSP 头符合预期。

**验收状态**：自动化全绿；**子龙 2026-11-28 02:47 在 30341 隔离实例真机验收通过**。验收通过后提交、tag `v0.3.4-beta.2` 并发布。
