# Pi Web Desktop：用 Tauri 2 给 pi-web 搭壳（macOS 首发，Windows 即时就绪，Linux 预留）

> 状态：**已批准**（2026-11-01）。本文件按批准时的原文存档，不再更新；实施中的偏差记在文末「事后补记」。
> 仓库：`~/zWork/ai/pi-web-desktop`

## 1. 目标与验收标准

目标：把 `agegr/pi-web`（Next.js 服务端 + 浏览器 UI）包成原生桌面 App。用户双击即用，不装 Node、不开终端、不碰浏览器；与命令行 `pi`、浏览器版 pi-web 共用同一份 `~/.pi/agent` 数据。

硬性验收（全部可复现验证）：

1. 双击 `.app`，冷启动 ≤5s 出现 pi-web 会话列表（实测本机 sidecar 就绪 2s）。
2. 把系统 `node` 从 PATH 移除后仍能启动（证明确实用的是自带运行时）。
3. 关窗退出后：`lsof -nP -iTCP:<port>` 无监听，`pgrep -fl sidecar` 无残留，`~/.pi/agent/pi-web-run/` 无本应用记录。
4. 桌面版新建的会话，在浏览器 pi-web 与 `pi` CLI 里都能立刻看到（共享数据）。
5. 当 30141 上已有**同版本**实例时，桌面版直接连上它，退出时**不杀**它；版本不一致时弹原生对话框让用户选。
6. 手测清单全过：SSE 流式回复、终端面板、文件预览（含 PDF）、导出 HTML 下载、拖拽上传、外部链接、会话「新标签页」、⌘C/⌘V/⌘A。
7. 手动 `kill -9` sidecar 后，界面 30s 内弹错误对话框，可一键重启并恢复。
8. 同一份代码在 Windows 上能 `tauri build` 出 NSIS 安装包并启动（CI 产出，不在本机验证）。
9. 产物体积预算：`.app` ≤700MB，`.dmg` ≤350MB，且裁剪后 `scripts/smoke` 仍通过。

## 2. 已核实的事实（决定架构的硬约束）

| 事实 | 来源 |
|---|---|
| pi-web 是 **Next.js 16 服务端应用**（`app/` 有 API routes、`proxy.ts`、`instrumentation.ts`），不是静态 SPA | 仓库源码 |
| 发布的 npm 包只含 `.next`(36MB)+`public`+`bin`，依赖安装时解析；必须用 Node 起服务 | npm tarball 解包 |
| 引擎要求 `node >= 22.19.0`；`node-pty` 自带 6 平台 prebuild（N-API，跨 Node 大版本可用，无需编译） | `npm view`、prebuilds 目录、`.node` 符号 |
| `node_modules` 实测 **562MB**（next 200 / @next/swc 96 / pi SDK 39 / pi-web 36 / node-pty 26 / sharp 27）；官方 node 22 二进制 108MB | 本机 `npm install` 实测 |
| `node bin/pi-web.js --no-open -p 31234` → **2s** 就绪，`GET /` 200，`/api/sessions` 正常；launcher 是父进程、`next start` 是子进程；SIGTERM 到 launcher 可干净退出 | 本机实测 |
| run record 写在 `~/.pi/agent/pi-web-run/<launcherPid>.json`：`{pid,nextPid,port,hostname,url,version,startedAt}`，退出自动删除 | 实测 + `bin/run-records.js` |
| launcher 会做 `previewModeId` 轮换（安全）、node 版本校验、信号转发 —— 不能绕过它直接 `next start` | `bin/pi-web.js` |
| 「Ready」行早于请求处理器就绪，探活必须用 `GET /`，不能解析 stdout | `docs/agents/client-platform.md` |
| 当前 Tauri：crate `2.12.5`；本机 `cargo tauri 2.1.0`（旧） | docs.rs / 本机 |
| `WebviewWindowBuilder` 有 `on_new_window`/`on_download`/`on_navigation`/`on_page_load`；`WindowConfig.drag_drop_enabled`（Windows 必须 false 才支持 HTML5 拖拽） | docs.rs 2.12.5 |
| `bundle.resources` 支持 map 形式 `{"../sidecar/": "pi-web"}`，保留目标目录 | docs.rs `BundleConfig` |
| macOS WKWebView **不支持 Service Worker**（除非 App-Bound Domains，而 macOS 不支持该配置） | docs.rs `limit_navigations_to_app_bound_domains` |
| 用户机器已有：npx 版 pi-web 跑在 `127.0.0.1:30141`（pid 46528）、`~/.pi/agent` 743MB、13 个项目会话、`pi` CLI 在 `~/.local/bin/pi` | 本机实测 |

## 3. 架构定案

```
Pi Web Desktop.app
├─ Rust (Tauri 2)                    窗口/菜单/生命周期/进程守护
│   ├─ 窗口直接导航 http://127.0.0.1:<port>
│   └─ 侧车管理（spawn/probe/kill）
└─ Contents/Resources/pi-web/        侧车
    ├─ runtime/node                  自带 Node 22.x（108MB）
    └─ app/{bin,.next,public,node_modules}   npm 装的 @agegr/pi-web@<pin>（562MB）
        └─ node bin/pi-web.js --no-open -p <port> -H 127.0.0.1
                └─ next start（子进程）
```

关键取舍（先讲清，避免以后反复）：

- **用官方 launcher，不自己起 `next start`**：preview secret 轮换、信号转发、node 版本校验都在 launcher 里，重写等于复制安全逻辑。
- **窗口直接导航到服务地址，不用 iframe**：pi-web 不设 `X-Frame-Options`，但 iframe 会引入第三方存储/Service Worker/弹窗等 WebKit 差异；代价是远程 origin 拿不到 Tauri IPC —— v1 设计成**完全不需要 IPC**（外链、下载、新窗口都用 Rust 侧回调），暴露面更小。以后若要接 pi-web 的 `pi-web:session-row-contextmenu` 原生右键菜单，再单独评估 `dangerousRemoteDomainIpcAccess`。
- **不 fork pi-web**：壳只依赖三个公开契约——CLI 参数、run record 文件格式、`GET /` 与 `/api/*`。上游变更靠 smoke 测试拦住。
- **自带 Node + 内置包**（已确认）：~600–700MB，换真正开箱即用。

## 5. 侧车构建（`scripts/fetch-sidecar.mjs`）

1. 读 `sidecar.json` pin 版本；`npm install @agegr/pi-web@<v> --omit=dev --no-audit --no-fund --prefix src-tauri/resources/pi-web/app`（本机实测 25s）。
2. 从 `https://nodejs.org/dist/v<v>/` 下载本平台包，**校验 `SHASUMS256.txt`**，只取 `bin/node`（Windows `node.exe`）到 `runtime/`，保留可执行位。
3. 裁剪（每步后跑 `smoke`）：删 `**/*.map`(8MB)、`**/*.md`(9MB，保留 LICENSE)、`@img/sharp*`(27MB，pi-web 已 `images.unoptimized`)、`node-pty` 非本平台 prebuilds(~20MB)、非本平台 `@next/swc-*`。目标 ≤500MB；达不到就如实写体积，不冒险删运行时必需文件。
4. 生成 `resources/pi-web/manifest.json`：piWebVersion、nodeVersion、平台、构建时间、文件数、SHA256 摘要，供启动自检与日志。
5. 跨平台：`--target <triple>` 决定下哪个 node、留哪些 prebuild；Windows 用 zip + `.exe`。

## 6. Rust 侧设计（`src-tauri/src/`）

- **`sidecar.rs`** — 解析资源目录（`app.path().resource_dir()/pi-web`，兼容 dev 的 `target/` 与 bundle 的 `Contents/Resources`，候选逐个试并记日志）；命令 `runtime/node app/bin/pi-web.js --no-open -p <port> -H 127.0.0.1`，`cwd=app/`。
  注入环境：`PI_WEB_NO_OPEN=1`、`PI_WEB_HOSTNAME=127.0.0.1`、`PORT`、`PI_WEB_SKIP_VERSION_CHECK=1`、`LANG/LC_ALL=en_US.UTF-8`、`TERM=xterm-256color`、`PATH=<runtime 目录>:<登录 shell 路径补全>`。
  Unix `process_group(0)`；Windows `creation_flags(CREATE_NO_WINDOW=0x08000000)`。stdout/stderr 按行写日志并保留最后 30 行给 splash。
- **`probe.rs`** — 零依赖探活：`TcpStream` + 手写 `GET / HTTP/1.1`，读状态行；150ms 间隔、90s 超时；判定沿用 pi-web 自己的「任何 HTTP 应答即就绪」。
- **`discovery.rs`** — 读 `~/.pi/agent/pi-web-run/*.json`（尊重 `PI_CODING_AGENT_DIR`），筛「URL 可应答 + `/api/sessions` 返回 JSON + version 等于内置版本」的实例用于附着；另维护自有 `app_config_dir/running.json`（launcherPid/nextPid/port）供上次崩溃清理，用命令行包含侧车路径防 pid 复用误杀。
- **优雅退出** — SIGTERM → 等 6s（launcher 自身 5s 兜底）→ 进程组 SIGKILL；Windows `taskkill /PID <pid> /T /F`。三处触发：`RunEvent::ExitRequested`、窗口 `Destroyed`、Drop guard；`⌘Q`/`⌘W` 同一条路径。
- **`menu.rs`** — `Menu::default()`（保证 WKWebView 里 ⌘C/⌘V/⌘A/⌘Z 可用）+ 自定义项：重新加载 `⌘R`、重启服务 `⌘⇧R`、在浏览器打开、复制服务地址、打开日志目录、DevTools（仅 dev）、退出。
- **窗口配置** — `windows: [{label:"main", create:false, url:"splash.html", title:"Pi Web", width:1280, height:860, minWidth:900, minHeight:600, dragDropEnabled:false, backgroundColor:"#0b0d12"}]`；setup 里 `WebviewWindowBuilder::from_config(...)` 挂回调后 build：
  - `on_navigation`：只放行 `http://127.0.0.1:<port>/*` 与 `tauri://localhost/*`。
  - `on_new_window`：同源同端口 → 开新窗口并聚焦（保留「新标签页开会话」）；外站 → `tauri-plugin-opener` 交系统浏览器，返回 Deny。
  - `on_download`：`Requested` 用 `tauri-plugin-dialog` 选路径（保住「导出会话 HTML」），`Finished` 后提示并可在 Finder 显示。
- 插件：`opener`、`dialog`、`single-instance`（二次启动聚焦已有窗口）。`withGlobalTauri: true` 供 splash；`csp: null`；不配置远程域 IPC。

## 7. 启动状态机（UX 核心）

```
读 config → 找已运行实例
   ├─ 同版本且 URL 可用 → Attached：导航到它，菜单标注「外部实例」，退出不杀
   ├─ 有但版本不同 → 对话框[连接 vX / 启动独立实例(默认) / 退出]
   └─ 无 → 选端口 → Spawn → Probe(90s)
                            ├─ Ready → Navigate http://127.0.0.1:<port>/
                            └─ 失败/进程退出 → splash 显示最后 30 行日志 + [重试][打开日志][退出]
运行期：每 10s 轻量探活；连续 3 次失败 → 原生对话框[重启服务 / 打开浏览器 / 退出]
```

- **端口必须稳定**：WKWebView 的 localStorage 按 origin（含端口）隔离，随机端口会让侧栏偏好/主题/语言/草稿每次重置。策略：首选 `config.port`（默认 30141），被占则 30142→30151 顺延，选中即写回 config 并固定；极端情况才 `127.0.0.1:0`（此时提示偏好不保留）。
- splash 通过 `window.__TAURI__.event` 收 `sidecar-status`（starting/attached/ready/failed + 版本 + 端口 + 日志尾）；失败页「重试」`invoke("restart_sidecar")`。

## 8. 配置与环境

`config.json`（`app_config_dir`）：`{port, attachPolicy:"same-version", proxy:null|"http://127.0.0.1:7890", extraEnv:{}, piCodingAgentDir:null}`。

- **代理默认关闭**：GUI 启动不继承你终端里的 `HTTPS_PROXY`；菜单加「使用本地代理 7890」开关，开时注入 `HTTP_PROXY/HTTPS_PROXY` 与 `NO_PROXY=localhost,127.0.0.1`（pi-web 服务端请求会遵守）。
- **`PI_CODING_AGENT_DIR` 默认不设**（共享 `~/.pi/agent`），高级用户可在 config 覆盖。
- `PI_WEB_IDLE_TIMEOUT_MS` 用默认 10 分钟（这是**会话内存驻留**回收，不是服务退出；设 0 会让 wrapper 常驻吃内存）。
- 日志：`app_log_dir()/sidecar.log`，5MB×3 滚动，菜单可打开目录。

## 10. 签名与打包

- `bundle.resources: {"../sidecar/": "pi-web"}`；`targets` mac `["app","dmg"]` / win `["nsis"]`；`minimumSystemVersion: "12.0"`。
- `entitlements.plist`：`com.apple.security.cs.allow-jit`、`allow-unsigned-executable-memory`、`disable-library-validation`（node JIT 与 `.node` 原生模块需要）。
- `scripts/sign-macos.sh`：由内到外 `codesign --force --options runtime --entitlements` 签 `node`、每个 `*.node`、`spawn-helper`，最后签 `.app`；`build` 后执行。签名前 `chmod +x` 断言 `spawn-helper` 可执行（否则终端功能静默失效）。
- 自动更新 v1 不做；升级 = 改 `sidecar.json` → 重建。README 写「壳版本 ↔ 内置 pi-web 版本」。

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| 体积 600–700MB（dmg 250–350MB） | 按平台只装一份依赖；裁 sharp/其它平台 prebuild；`sidecar.json` 留 `mode:"thin"` 口子（首次下载），架构不变 |
| 两服务同写同一会话文件 | 优先附着同版本实例；版本不同让用户显式选；启动清理自有孤儿 |
| pi-web 上游破坏契约 | 只依赖三个公开契约 + 每次升级跑 smoke；版本 pin |
| WKWebView 无 SW / PDF iframe / 拖拽差异 | M1 就实测这四点，写入 README「已知差异」，不改上游源码 |
| `pi-web stop` 会停掉桌面版服务 | 属预期（同一 run record 体系），健康监控弹窗一键重启 |
| 首次启动被杀软/公证扫描拖慢 | 90s 超时 + splash 实时显示 stderr，避免白屏无反馈 |
| cargo 拉 crates 慢 | 已确认本机 `~/.cargo/config.toml` 走 tuna 镜像；CLI 用 `@tauri-apps/cli@^2`（本机 `cargo tauri 2.1.0` 太旧） |

## 事后补记（实施中的偏差，仅供追溯，不属于批准时的计划）

**实施日期：2026-11-01（M0 + M1 + M2 大部分一次做完）**

结构与构建上的偏差：

1. **侧车生成物位置**：实际放仓库根 `sidecar/`（计划写的 `src-tauri/resources/pi-web/`），`bundle.resources` 用 map 形式 `{"../sidecar/": "pi-web"}`。dev 下 `tauri-build` 会把 `sidecar/` 复制到 `target/debug/pi-web/`（每次 sidecar 变更才复制），所以 dev 与 bundle 的运行时布局一致，资源目录解析逻辑只多一条 dev 退路。
2. **包内路径**：`npm --prefix sidecar/app` 装出来的布局是 `sidecar/app/node_modules/@agegr/pi-web/`，入口为其中的 `bin/pi-web.js`，cwd 必须是这个包目录（launcher 用 `__dirname/..` 当 pkgDir）。计划里写的 `app/{bin,.next}` 层级不成立。
3. **裁剪效果远超预期**：source map 实测 124MB（计划估 8MB）、文档 7MB、sharp+@img 28MB、其它平台 node-pty prebuild 23MB；侧车最终 **404MB**（计划预算 600–700MB），`.app` 约 400MB 量级。
4. **启动耗时**：首次独立启动 4.2s（含 next.config 编译），后续 1.7–2.0s，好于 5s 验收线。
5. **孤儿清理改了判定方式**：不再依赖 `ps` 命令行（受限环境里 `ps` 可能不可用），改用 pi-web 自己的 run record（`<agentDir>/pi-web-run/<pid>.json` 的 pid+port+version 三项对齐），`ps` 仅作退路。这条在实测中救过一次误判。
6. **splash 与事件的竞态**：Rust 启动线程比 splash 页面加载更早，`sidecar-status` 事件会丢。补了 `get_status` 命令：页面加载后主动拉一次最后状态。
7. **失败对话框**：「退出 / 查看日志」两个按钮现在真的生效（原先只弹不处理）。
8. **菜单「复制服务地址」**：M1 只写日志，未引 `tauri-plugin-clipboard-manager`（少一个依赖，功能后补）。
9. **下载**：固定落 `~/Downloads`，尚未接原生保存路径对话框。
10. **release 构建踩到 macOS 27 的坑（已定位 + 已修）**：`tauri build` 在编译 proc-macro 时报 `mis-aligned LINKEDIT string pool`，随后是莫名其妙的 `can't find crate for phf_macros` / `zerofrom_derive`。根因不在我们的代码：macOS 26/27 的 dyld 要求 `LC_SYMTAB` 字符串池 8 字节对齐，而 cargo 的 release 默认 `strip = "debuginfo"` 会作用到构建依赖（含 proc-macro），Rust < 1.99 用内置 LLVM objcopy 原地 strip 后只剩 4 字节对齐，dyld 拒绝加载，rustc 便把它报告成"找不到 crate"。修复 = `src-tauri/Cargo.toml` 加 `[profile.release.build-override] strip = false`（只影响 proc-macro / build script，不进产物，体积无变化）。参考 rust-lang/rust#157750 与多个同症状 issue；升级到 Rust ≥ 1.99 后此条可删。

11. **健康监控重写（用户实测发现的 bug）**：原实现把端口捕获进监控线程闭包，附着外部实例后再「重启服务」，旧线程仍在盯已死的旧端口 → 反复弹「服务已停止响应」。改为全局唯一线程、每轮重读当前端口与模式、一次故障只告警一次，并把 `Starting/Failed` 期间排除在探测之外。验证方式加了两个环境变量（`PIWEB_HEALTH_INTERVAL_MS` / `PIWEB_HEALTH_HEADLESS`），可在不点对话框的情况下自动化复现与验证。

12. **PATH 改为继承登录 shell（用户测试会话反馈的第二个问题）**：原实现只写死补了 `.local/bin`/homebrew 等 11 项，漏掉 nvm 等版本管理器目录，导致会话里 `mnemon`/`pnpm` 等 command not found。现在：登录 shell PATH 缓存优先 → 常见目录兜底（nvm 按 alias/default 优先）→ 继承值 → 包内 runtime 放最后（保证会话里的 `node` 与终端一致）；`zsh -lic` 探测放后台（GUI 里会卡 1s+）、成功缓存 7 天。实测侧车与终端的 `node`/`pnpm`/`mnemon`/`git`/`python3` 解析完全一致。
